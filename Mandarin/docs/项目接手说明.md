## 0. 项目是什么

Qt 6.6.3 + C++20 桌面 AI 桌宠（Windows / macOS / Linux）。三窗口：**Tachie（立绘，无边框+鼠标穿透）**、
**Dialog（聊天气泡，业务枢纽）**、**MainWindow（设置面板，ElaWindow 导航）**。
功能面：AI 对话（多服务商）、语音合成（本地 vits-simple-api）、语音唤醒/离线识别、屏幕捕获、联网搜索、
日程提醒、应用启动、摄像头感知、**Live2D 立绘**（2026-09 新增）。

**当前版本 `1.14.3`；最新 Release `v1.14.3`（2026-09-11，标记 Latest）。**
**这一整轮 Live2D 工作尚未发布**——下一次发布应为 **1.15.0**。

## 2. 绝对不要做的事（硬红线）

1. **不要自动启动桌宠**。`启动.bat` 永远由用户执行；验证编译只用"产物存在/无报错"，不要为了验证去跑 GUI。
2. **链接 `Mandarin` 前先确认 `Mandarin.exe` 没在跑**，否则 `LNK1104`（文件被占用）。
3. **模型文件绝不入库、绝不入包**：Live2D 模型（`Documents/Mandarin/Live2D/**`）与 vits 模型都受作者授权约束
   （**禁二传 / 禁二改**）。它们已在 `.gitignore` 里，**不要**用 `git add -f` 绕过。
   我们自己写的**映射/预设数据**可以入库（已放在 `Mandarin/assets/live2d-presets/`，只含参数名与范围，不含模型）。
4. **不要写用户的 `config.ini`**。测试要读配置必须走 `MANDARIN_CONFIG_INI` 环境变量重定向到临时文件
   （窗口侧 `settingsPath()` 已支持）。**验证方式**：跑测试前后对真实 `config.ini` 做 SHA256 比对。
   （历史事故：测试把用户设的 `live2dFps=120/live2dScale=1.5` 清成了 `60/1`。）
5. **不要不经询问就给机器加压**（起烧 CPU 的进程）。需要负载**先问用户**，且加压器必须**自终止**、
   结束时**验证进程真的消失**（别用 `-ErrorAction SilentlyContinue` 吞掉清理错误）。
6. **测试不全绿不许提交**。一个会"叫狼来了"的红/脆测试比没有测试更糟。
7. **不要相信任何转述的"已通过"**（包括子代理的）：**自己复跑**。真实发生过"转述 9/9，实际 1 个失败"。

## 3. 关键约定（改代码前必须知道）

- **AI 回复格式**：系统提示词要求 `心情|中文|日语|内心独白`，用 `|` 解析。
  **心情段的值必须取自该角色 `Character/Assets/<角色>/Tachie/` 下 PNG 的文件名**（App 用文件名生成可选心情列表）。
- **配置写入**：各设置页在值变更时立即写文件，然后 emit 信号让 Dialog 重载。
- **线程模型**：以主线程为主，无 QThread；**例外**是语音识别解码与截屏 JPEG 编码用 `std::thread`，
  完成后 `QMetaObject::invokeMethod(Qt::QueuedConnection)` 回主线程。
  ⚠️ **Live2D 渲染目前跑在主线程**：120fps 的预算是 8.33ms/帧，实测 atri 1.5× ≈ 4.2ms、miku 1.5× ≈ 6.2ms
  （miku 已占 78%）。想让高倍率不挤占主线程，正解是**渲染线程**（方案里的主方案）。
- **VITS 语音**：本地 HTTP 服务（仓库根 `vits-simple-api-windows-cpu-*`），Dialog 用
  `QNetworkAccessManager` 拉音频 → `QMediaPlayer` 播放。**服务默认返回 WAV（16bit PCM）**，
  口型包络就是解析它算出来的；不存在解码器依赖。
- **代码风格**：C++20；类 PascalCase；成员 `m_` 前缀；JSON 用 `ZcJsonLib`；**注释要写"为什么"**（本仓库传统）。
- **行尾**：仓库索引是 **CRLF**。改动文件不要引入整文件 EOL 重写（提交前看 `git diff --stat` 是否只有增量）。
- **Live2D 数据分工**：**词表属于角色**（心情名 = 该角色立绘文件名），**参数属于模型**
  （`parameter-map.json` 的语义名 → 该模型真实参数 ID + 范围）。所以同一份 `moods.json` 的别名表对所有模型通用，
  只有原型数值要按模型各自标定。详见 `docs/Live2D交接.md` §3。

## 4. GitHub 提交流程（说「提交」= **全套**）

> 用户说「**提交**」时，指的**不是**只 `git commit`，而是下面这一整串。
> 只是普通存档提交时，用普通 `git commit`（**不升版本、不打包、不发 Release**），并在回复里说明这是普通提交。

### 4.1 全套流程（按顺序）

1. **测试全绿**：`ctest --test-dir build2 -C Release` → 必须 100%（当前 10 个目标）
2. **提交并推送**：`git add` → `git commit` → `git push origin master`
   - ⚠️ 提交信息含**中文或引号**时，**写到文件再 `git commit -F <文件>`**；PowerShell 会把内嵌引号拆成 pathspec
     （本会话踩过：消息被当成文件名，报 `pathspec 'must' did not match`）
3. **升版本**：改 `Mandarin/CMakeLists.txt` 的 `project(Mandarin VERSION x.y.z)`
   - 新功能 → 次版本 +1（如 1.14.3 → **1.15.0**）；仅修 bug → 修订号 +1
   - 改完**必须重新 configure**，否则 `build2/Version.h` 不更新
4. **重新构建 Release**：`cmake --build build2 --config Release --target Mandarin`
5. **打包 portable zip**
   - 内容 = **`build2/Release/**` 全量（排除 `*.zip`）**
   - 命名 = **`Mandarin-v<版本>-portable.zip`**（例：`Mandarin-v1.14.3-portable.zip`，约 197MB）
   - ⚠️ **打包前确认没有多余大文件**：历史上误带过 fp32 `model.onnx`，包体膨胀到 **1GB**
6. **更新 GitHub Release 并标记 Latest**
   - 仓库：`Mandarin715/Mandarin`（SSH：`git@github.com:Mandarin715/Mandarin.git`）
   - `gh` CLI **已装且已登录 `Mandarin715`**，可直接发布
   - **标题约定**：`Mandarin v<版本> — <一句话摘要>`（例：`Mandarin v1.14.3 — 搜索更智能（缺主题先反问 + 否定重搜）`）
   - 资产：上传上面的 portable zip；**必须标记为 Latest**（用户明确要求）
   - 参考命令（按需调整摘要与资产路径）：
     ```powershell
     gh release create v1.15.0 "build2\Release\Mandarin-v1.15.0-portable.zip" `
       --title "Mandarin v1.15.0 — <一句话摘要>" --notes-file <说明.md> --latest
     ```
7. **清理临时缓存**：清掉本轮产生的临时文件/临时构建目录（别把中间产物留在仓库根或 `build2/Release`）
8. **汇报**：版本号、提交哈希、包名与体积、Release 链接

### 4.2 备选：CI 发布

`.github/workflows/manual-win-linux-release.yml`（名称 `Build and Release (Windows Portable)`）——
**手动触发**（`workflow_dispatch`），入参 `tag_name`（例 `v1.6.1`）；在 `windows-latest` 上
Ninja + MSVC + `jurplel/install-qt-action` 构建、`windeployqt` 部署、打包成 `Mandarin-<tag_name>-portable.zip`。
**它不会替你提交代码**，只负责构建与发布产物。

### 4.3 两个要提醒用户的坑

- **`CHANGELOG.md` 已落后 7 个版本**：遵循 Keep a Changelog 格式（`## [x.y.z] - YYYY-MM-DD` + `### 新增/优化/修复`），
  但**最后一条是 1.7.1**，而项目已到 1.14.3。发版时要不要补写，需要用户决定。
- **本地 `git tag` 与 GitHub Release 不完全同步**：以 `gh release list` 为准（`git tag` 看到的可能是本地未 fetch 的旧集合）。

## 5. 注意事项（踩过的坑，按"会不会让人做错事"排序）

### 5.1 会让人做错事的

| 坑 | 正确做法 |
|---|---|
| 从 `*.vtube.json` / `*.cdi3.json` 抄参数范围 | **范围只能来自模型自己声明的值**（`CubismModel::GetParameter{Minimum,Default,Maximum}Value`，渲染器已封装为 `declaredParameterRanges()`）。抄 vtube 那次 **27 条错 4 条** |
| 以为 moods 原型是"相对 neutral 的增量" | 实际是**绝对目标值覆盖**（`parametersForArchetype()` 先填 neutral 再覆盖，**不相加**）。代码里变量名 `m_archetypeDeltas` 是**误称** |
| 以为"观感问题"能靠断言确认 | **必须看图**，而且常常要**放大**（1:1 看不出清晰度差别，2× 最近邻才看得出）。结论性判断要有图 |
| 用单次采样下结论 | 我犯过两次：①"15721 返回 200 就说明已恢复"（本地 200 不代表上游通）②"没看到代理进程就说明代理死了"（其实撞进重启空窗）。**要重复采样 + 交叉验证** |
| 以为测试"通过"就等于在验证 | 发生过**假绿**：用 `continue` 跳过全部比较而"通过"。新测试要加**防空断言**（如 `comparedPieces > 0`） |
| 负载下测"相邻帧" | 帧步长来自墙钟且**被夹在 0.1s**，机器一抢占"墙钟"与"虚拟时间"就脱钩（漂移从 0~5px 涨到 1276/4121px）。用注入 API `setNextFrameDeltaSeconds()` 钉住虚拟时间 |

### 5.2 构建/环境

- **Windows 构建需要**：WinRT（Windows SDK 10.0.26100.0）+ `/std:c++20` + 显式
  `#include <winrt/Windows.Foundation.Collections.h>`，并链接 `windowsapp.lib ole32.lib oleaut32.lib`。
- **沙箱内 MSBuild 可能因重复 `Path/PATH` 在调用 CL 前失败** → 需要在沙箱外构建（Codex 上轮遇过，经用户批准后成功）。
- 存在 `build/`（旧）与 `build2/`（当前）两个构建目录，**用 `build2`**。
- `3rdparty/` 里有自研库与 sherpa-onnx；**Live2D SDK 在 `Mandarin/3rdparty/Live2DCubismSDK/`（gitignore 内）**，
  SDK 缺席时项目会自动退化成 PNG 构建（这是设计，不是错误）。

### 5.3 本机环境依赖（会表现成"代码好像坏了"）

- **代理链路**：Codex 走 `CC Switch` 本地中转（`http://127.0.0.1:15721/v1`，`wire_api=responses`）
  → 出口代理 `clash-verge / verge-mihomo`（`127.0.0.1:7897`）→ 上游。**任一环断掉都会表现为请求失败**：
  - `502 转发失败: 连接失败` = 出口代理不可用（例：它正在重启）
  - `401 API keys are not supported by this endpoint` = 用 API Key 访问了**只认 ChatGPT 账号登录态**的端点；
    而且 `gpt-6.1-sol` 这类 **work-mode 模型只存在于 ChatGPT 订阅后端**，API Key 永远不行 → 必须账号登录
  - 三步自查：
    ```powershell
    curl.exe -s -o NUL -w "%{http_code}" --noproxy "*" --max-time 5 http://127.0.0.1:15721/v1/models   # 本地中转活否
    Get-NetTCPConnection -LocalPort 7897 -State Listen                                                   # 代理活否
    curl.exe -s -o NUL -w "%{http_code}" --max-time 10 -x http://127.0.0.1:7897 https://api.openai.com/v1/models  # 出口通否(401=通)
    ```
- **语音服务**：`vits-simple-api-windows-cpu-*`（`启动.bat` 会自动拉起；端口 23456）。首次加载 GPT-SoVITS 需数十秒。

## 7. 验证纪律（怎么证明"做完了"）

1. `ctest --test-dir build2 -C Release` **10/10 全绿**才算完
2. **新断言必须在旧代码上失败**，并留下 RED 证据（失败信息 + 数字）
3. **"防御型"断言要用变异测试证明它有牙**：把生产代码改坏 → 看它是否变红 → 改回
4. **观感问题看图**（必要时放大）；**性能问题报数**（`reportsFullPipelineFrameCost`，用户档位 `120fps/1.5×`）
5. **数据改动后同步仓库备份**并核对两份 SHA256 一致
6. **测试前后核对真实 `config.ini` 的 SHA256**（先取基准）
7. 报数要**诚实**：说不确定就说不确定；做不到就说做不到（本仓库的传统是"承认做不到"比"假装做到"更被看重）
