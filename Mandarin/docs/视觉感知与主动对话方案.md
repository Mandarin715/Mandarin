# 视觉感知 + 主动对话方案（待实施）

> 2026-07-04 设计，暂不实施

## 目标

1. 桌宠通过摄像头"看到"用户，感知用户状态
2. 桌宠能主动发起对话，而非仅被动应答

## 架构

```
┌──────────────────────────────────────────────────────┐
│                    触发源                             │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────┐   │
│  │ 空闲计时器 │  │ 屏幕截图  │  │ 摄像头（可选）     │   │
│  │ 已有      │  │ 已有      │  │ 新增 ~15行代码    │   │
│  └────┬─────┘  └────┬─────┘  └────────┬─────────┘   │
│       └──────────────┼───────────────┘               │
│                      ↓                               │
│             决策上下文构建器                           │
│   当前时间 + 上次交互间隔 + 位置 + 屏幕/摄像头内容     │
│                      ↓                               │
│             LLM 决策：该不该说话？                     │
│     SPEAK|想说的话   or   SILENCE                     │
│                      ↓                               │
│             SPEAK 时：走正常对话流程                   │
│             TTS 播放 → 显示在聊天框                    │
└──────────────────────────────────────────────────────┘
```

## 摄像头捕获

Qt6 原生支持，约 15 行代码：

```cpp
QCamera *camera = new QCamera(QMediaDevices::defaultVideoInput());
QMediaCaptureSession session;
QVideoSink *sink = new QVideoSink;
session.setCamera(camera);
session.setVideoSink(sink);

connect(sink, &QVideoSink::videoFrameChanged, [=](const QVideoFrame &frame) {
    QImage image = frame.toImage();
    // → 后面走已有的 JPEG → Base64 → Vision API 流程
});
camera->start();
```

## 主动对话决策流程

每 30 秒（可配置）触发一次：

```
1. 收集上下文：
   - QDateTime::currentDateTime()      ← 已有
   - 上次交互时间戳                      ← 新增成员变量
   - m_cachedLocation                  ← 已有
   - 屏幕截图 (可选)                    ← 已有 captureScreenToJpeg()
   - 摄像头截图 (可选)                   ← 新增

2. 构建决策 Prompt → 发给 LLM（复用已有 AiProvider 配置）：

   [当前时间] 2026-07-04 20:30
   [上次交互] 12 分钟前
   [用户位置] 上海
   [用户记忆] 名字：小明, 爱好：编程
   [屏幕内容] 用户在浏览技术博客
   
   判断是否应该主动说话。格式：SPEAK|心情|中文|日语 或 SILENCE
   规则：
   - 空闲超 5 分钟可考虑说话
   - 屏幕内容是娱乐/放松 → 可以聊聊
   - 屏幕内容是工作/学习 → 简短问候或不打扰
   - 用户可能离开时 → 不打扰
   - 早上/午休/晚间时段 → 合适的时间问候

3. 如果 LLM 返回 SPEAK → 走正常对话回复流程：
   - 显示在聊天框
   - 切换表情
   - TTS 播放日语
   - 如果用户在连续对话模式 → 说完后自动开始等用户回复
```

## 信息源优先级

| 优先级 | 信息源 | 实现难度 | 价值 |
|--------|--------|----------|------|
| P0 | 空闲时间 + 时段 | 0 天（全是现成的） | 高 |
| P1 | 屏幕内容 | 0.5 天（复制 captureAndAnalyzeScreen） | 最高 |
| P2 | 记忆 + 搜索/天气 | 0.5 天（已有 SearchProvider） | 中 |
| P3 | 摄像头 | 0.5 天（新增 15 行） | 中 |

## 场景示例

| 触发条件 | 桌宠主动说的话 |
|----------|---------------|
| 空闲 10 分钟 + 屏幕是娱乐内容 | "你刷视频的样子好认真呀，看到什么有趣的了？" |
| 早上 8:30 + 空闲 5 分钟 | "早安！今天上海 25°C，适合出门哦~" |
| 用户打开游戏 | "哇，要打游戏了吗？加我一个！" |
| 凌晨 1 点 + 屏幕还在亮 | "这么晚还在看代码？明天会困的……" |
| 用户起身离开（摄像头） | "路上小心，早点回来哦！"（然后休眠） |
| 用户回来（摄像头） | "你回来啦！我刚刚在想你呢～" |
| 用户长时间盯屏幕不动 | "盯了这么久屏幕，休息一下吧？" |

## 和现有功能的复用

- Vision API 管道 → 复用 `captureScreenToJpeg()` + `analyzeScreenWithVision()`
- AI 调用 → 复用 `configureAiProvider()`
- 回复处理 → 复用 `replyReceived` 的信号链（表情+显示+TTS）
- 搜索触发 → 复用 `SearchProvider`
- 定位 → 复用 `m_cachedLocation`

## 风险

- macOS 需在 Info.plist 声明 `NSCameraUsageDescription`
- 频繁调用 Vision API 有成本（每 30 秒一次，可调大间隔）
- 用户隐私：摄像头数据不应存储或上传到非 Vision API 之外的地方
