# 智能助手方案（待实施）

> 2026-08-22 设计。目标：把桌宠从「会聊 + 会描述屏幕」升级为「能帮你整理/归纳内容的助手」，基于它已有的**屏幕识别 + 多模态视觉**优势。v1 只做安全区：**看懂 → 理好 → 给你**，不碰文件系统、不操作电脑。

## 目标

让桌宠能帮用户干"轻活"：
1. **总结 / 归纳** 屏幕上的内容（网页、文档、代码、表格、聊天）
2. **整理 / 归纳** 文本内容（剪贴板里复制的、或直接粘贴给它的）
3. 产出**结构化结果**（清单、要点、表格、分类），而不是一句"屏幕上有个网页"

不追求自主跑复杂流程、不操作鼠标键盘、不动文件。

### 缺的东西

1. **没有"任务动词"识别** — "总结/归纳/整理/分类"这些请求目前会落进普通聊天或"描述屏幕"，而不是"按任务处理"
2. **视觉/文本只"描述"，不"加工"** — prompt 固定是"描述你看到什么"，没有"按用户指令整理"
3. **没有结果承载面板** — 长结果（清单/表格）塞不进聊天气泡
4. **剪贴板内容没被当数据源** — 已有监听，但没用于"整理你复制的内容"这个场景

## 设计方案

### 任务识别（接进现有优先级链）

在 `doSubmitCurrentInput` 的优先级链中，**屏幕捕获分支之前**插入一个「智能助手任务」检测步骤：

```
0. 日程提醒拦截
── ✨ 智能助手任务检测（本次新增）──
    命中(任务动词 + 数据源) → TaskAgent
1. 屏幕捕获关键词（原"描述屏幕"）
2. 搜索关键词
3. 应用启动匹配
4. AI 意图分类
5. 普通聊天
```

**任务动词表**（命中即判定为"整理类请求"）：
`总结 / 概括 / 归纳 / 提炼 / 精简 / 整理 / 分类 / 归类 / 列要点 / 列出要点 / 做成表格 / 做成清单 / 对比 / 要点`

**数据源识别**：
| 源 | 判定 |
|----|------|
| 屏幕 | 含「屏幕 / 截图 / 屏幕上 / 看看屏幕 / 屏上」 |
| 剪贴板 | 含「剪贴板 / 复制的内容 / 刚复制的 / 这段文字」 |
| 粘贴文本 | 输入本身就是大段文本（> 40 字且无明显任务动词也可能被当"待整理内容"，见下） |

**触发策略（关键词 + AI 意图双保险）**：
- 任务动词命中 **且** 数据源明确 → 直接进 TaskAgent；
- 任务动词命中但数据源不明 → 交给现有 AI 意图分类兜底判断"这像不像一个整理请求"，是则再补问/默认走剪贴板；
- 输入是粘贴的大段文本 → 视为"待整理内容"，用默认任务（归纳要点）处理。

### 数据源获取

| 源 | 取法 | 走的模型 |
|----|------|----------|
| 屏幕 | 复用 `captureScreenToJpeg()` | 视觉 API（复用 `analyzeScreenWithVision` 的端点/Key/Model 配置，`screenCapture/*`） |
| 剪贴板 | `QGuiApplication::clipboard()->text()` | 对话 LLM（复用现有 AiProvider 配置） |
| 粘贴文本 | 用户输入原文 | 对话 LLM |

> **剪贴板隐私**：只有当用户输入明确提到"剪贴板/复制的"时才读剪贴板，不做隐式读取。

### TaskAgent（新增）

```cpp
enum class TaskSource { Screen, Clipboard, PastedText };

enum class TaskVerb {
    Summarize,      // 总结/概括
    ExtractPoints,  // 归纳要点
    MakeList,       // 整理成清单
    MakeTable,      // 做成表格
    Categorize,     // 分类/归类
    Compare,        // 对比
    General         // 通用整理（默认）
};

class TaskAgent : public QObject
{
    Q_OBJECT
public:
    void runTask(TaskSource source,
                 TaskVerb verb,
                 const QString &rawText,        // 剪贴板/粘贴文本
                 const QByteArray &screenshotJpeg, // 屏幕源
                 const QString &extraInstruction); // 用户附加要求

signals:
    void taskFinished(const QString &result, const QString &summaryLine);
    void taskFailed(const QString &reason);
};
```

- **屏幕源**：`TaskAgent` 内部构建视觉请求（复用 `screenCapture/*` 配置 + 端点选择逻辑，建议从 `analyzeScreenWithVision` 抽出一个共用的 `buildVisionRequest(prompt, imageBase64)` 避免重复），但 **system prompt 换成按任务动词生成的模板**（如"把这张截图里的内容整理成一份要点清单"）。
- **文本源**：走对话 LLM，同一套任务 prompt 模板。
- **任务 prompt 模板**（按 verb 生成，统一要求：中文、结构化、直接给结果不寒暄）：
  - Summarize → "用 3~5 句概括核心内容"
  - ExtractPoints → "列出要点（markdown 无序列表）"
  - MakeList → "分类整理成清单"
  - MakeTable → "整理成 markdown 表格"
  - Categorize → "按主题分组"
  - Compare → "分点对比异同"

### 结果呈现（方案①，已定）

| 结果类型 | 呈现 |
|----------|------|
| **短结果**（≤ 200 字且无列表/表格） | 作为桌宠回复显示在气泡，走现有 `appendHistoryLine` + 心情/独白 |
| **长结果**（清单/表格/归纳） | 弹 `TaskResultPanel`（滚动查看 + 「复制到剪贴板」按钮） |

- 长结果同时给一句**简报**进气泡（如"整理好了，共 5 条要点，点开查看"）。
- 可选（v1.1）：VITS 朗读简报；结果自动写入剪贴板。

### 与现有功能关系

| 功能 | 关系 |
|------|------|
| `analyzeScreenWithVision` | 抽取共用的 `buildVisionRequest()`；**原"描述屏幕"分支保留不动**，任务分支在其之前分流 |
| `captureScreenToJpeg` | 直接复用 |
| 优先级链 `doSubmitCurrentInput` | 在屏幕捕获分支前插入任务检测步骤 |
| 对话 AiProvider / 搜索 / 日程 / 记忆 | 文本源复用 AiProvider；其余不动 |
| 剪贴板监听 | 已有，本次只用其读取能力 |

### 明确不做（v1 边界）

- 不操作文件系统（不移动/重命名/删除文件）
- 不点鼠标、不敲键盘（不做计算机使用 agent）
- 不做多步自主流程、不做联网搜索增强（搜索已有独立分支）
- 不加新设置页（v1 复用现有 screenCapture 与 LLM 配置；开关留 v2）

## 风险

| 风险 | 对策 |
|------|------|
| 误触发（普通聊天被当任务） | 任务动词 + 数据源双条件；数据源不明交 AI 意图兜底 |
| 剪贴板隐私 | 仅在用户明确指"剪贴板/复制的"时读取 |
| 视觉结果质量差 | prompt 模板按任务细化；复用已验证的视觉端点配置 |
| 长结果渲染卡顿 | 结果面板只渲染纯文本/markdown，无复杂控件 |
| 与"描述屏幕"语义冲突 | 任务检测在其之前分流，原分支不动，互不干扰 |
| 端点/Key 配置漂移 | 抽取 `buildVisionRequest` 统一走 `screenCapture/*` 配置，单一来源 |
