# B 阶段：明确请求换装与震惊白眼

2026-09-30。默认维护亚托莉，未修改角色、模型或 VITS 配置。Release 已构建，桌宠由用户自行启动。

## 使用

- 明确要求“换上睡衣”“把睡衣换上吧”“换上比基尼”“穿回平时的衣服”“换上凉鞋”“换回默认鞋”。AI 需确认并返回动作数据，验证后更新当前装扮，选择保留在本次窗口会话。
- 普通聊天提到衣服、回忆、否定、假设及目标未明确的请求不换。第一版保守识别常用中文指令，未匹配到的表达需要改为明确目标的指令。
- AI 输出心情为震惊、惊讶、吃惊、惊愕、惊呆或惊吓时，叠加临时白眼。整条语音完成后撤销；分句间停顿不撤销。取消回复、重置语音管线或聊天出错时清理。无语音的文字回复保留约 2.5 秒。
- 临时白眼独立于手动装扮：结束时恢复手动设置，不更改衣服鞋子；若用户本来手动开启白眼，则保留该选择。

## 数据与接线

四段回复保持原顺序，仅换装时追加第五段 JSON。没有内心独白也须保留空的第四段：

```text
快乐|我换上睡衣啦！|パジャマに着替えました！||{"appearance":{"clothes":"pajamas"}}
```

`ReplyAppearanceIntent` 根据原始用户输入识别明确目标，并要求 JSON 中的字段与目标完全一致；错误 JSON、额外字段、部分动作、未知动作和不相符的选择全部拒绝。仅开放 clothes/shoes。震惊白眼由心情和语音生命周期驱动，AI 无权通过装扮 JSON 操作血衣等特殊道具。

Live2D 再次对动作做模型选项校验，原子提交到现有装扮层。手动选择、AI 选择及复位都通过 appearanceStateChanged 把实际状态同步给 Dialog，下一轮提示词使用最新状态，不写真实配置文件。

涉及换装的请求先收完整回复并校验动作，再启动语音；其他回复保留原分句合成。分句合成只读取第三段日语，避免内心独白或 JSON 进入 TTS。

Dialog 在首个完整心情字段到达时发送 requestReplyExpression；仅 AI 回复结束、合成待办/网络请求/就绪音频都为空、播放器停止时发送 requestReplyExpressionFinished。播放器的单句 StoppedState 不直接撤销白眼。旧轮取消和文字回复延时采用代次校验。

## 验证

- `test_characterwindowbase`：常用命令、否定/回忆/假设/提及、装扮与输入不相符、禁止道具、错误 JSON、部分动作及多余字段。
- `replyAppearanceAndShockLifecycle`：真实 ATRI 模型参数，AI 换装与状态同步、非法动作原子拒绝、白眼 Param22=30、分句暂停保留、整条结束恢复、期间手动换装保留、手动白眼选择保留、新回复清除临时状态。
- 原有装扮、数据边界及原生右键/拖动回归一并通过。专项日志 `build2/reply-appearance-shock-final.log`。
- 主程序编译通过；未自动启动桌宠，未调用真实 LLM 或播放真实 TTS。Dialog 尚无整体测试目标，真实服务返回格式及语音播放需用户启动后体验。
