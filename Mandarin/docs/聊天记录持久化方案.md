# 聊天记录持久化 + 会话切换方案（待实施）

> 2026-07-04 设计，暂不实施

## 目标

让桌宠的聊天记录像 ChatGPT 一样：
1. **持久化** — 每次聊天完整保存到磁盘，关掉重开不丢失
2. **会话分离** — 不同时间段的聊天分成独立的"会话"
3. **可切换** — 侧边栏查看所有历史会话，点进去继续聊
4. **新建对话** — 随时开新会话，旧会话自动归档

### 缺的东西

1. **没有"会话"概念** — 所有对话混在一个大数组里，永远追加，不区分"上次聊的"和"今天聊的"
2. **没有会话列表** — 用户看不到有哪些历史对话，只能看单条消息
3. **没有"新建对话"按钮** — 无法主动开始一段新会话
4. **没有会话元数据** — 没有标题、时间戳、消息预览
5. **历史窗口太简陋** — 展示的是逐条消息而不是分组会话，回溯只能截断而不能真正"切换"
6. **退出时不保存** — 如果退出前 2 秒内发了消息，那轮对话会丢失
7. **rewind 前不保存** — 回溯到历史某条消息时，当前对话不会先存档

## 设计方案

### 数据结构

```
Documents/Mandarin/Character/UserConfig/<角色>/
├── context.json              # 保留，存当前活跃会话的上下文（兼容旧版）
├── memory.json               # 不变
└── sessions/                 # ✨ 新增：会话存档目录
    ├── index.json            # ✨ 会话索引（元数据列表）
    ├── 2026-07-04_203015.json # 会话1（会话ID = 创建时间戳）
    ├── 2026-07-03_180022.json # 会话2
    └── ...
```

#### index.json（会话索引）

```json
{
  "sessions": [
    {
      "id": "2026-07-04_203015",
      "title": "今天天气好热啊",
      "created": "2026-07-04T20:30:15",
      "updated": "2026-07-04T21:15:42",
      "messageCount": 24
    },
    {
      "id": "2026-07-03_180022",
      "title": "帮我写个排序算法",
      "created": "2026-07-03T18:00:22",
      "updated": "2026-07-03T18:45:10",
      "messageCount": 18
    }
  ],
  "activeSession": "2026-07-04_203015"
}
```

- `title`：取会话第一条用户消息的前 15 字
- `activeSession`：当前活跃的会话 ID，启动时自动加载

#### 单个会话文件（如 `2026-07-04_203015.json`）

```json
{
  "id": "2026-07-04_203015",
  "created": "2026-07-04T20:30:15",
  "updated": "2026-07-04T21:15:42",
  "messages": [
    {"role": "user", "content": "今天天气好热啊", "time": "2026-07-04T20:30:15"},
    {"role": "assistant", "content": "开心|是啊，夏天真的来了|夏が来たね", "time": "2026-07-04T20:30:18"}
  ]
}
```

用结构化 `{role, content, time}` 替代原来的纯文本 `"用户：xxx"`，好处：
- 渲染历史列表时可按角色区分样式
- 精确时间戳不用靠解析字符串
- 未来可做导出/搜索

### 兼容性处理

```
启动时：
  1. 尝试加载 sessions/index.json
  2. 如果不存在（旧版本升级）：
     a. 读取旧 context.json 的 history 数组
     b. 将其转换为一个会话 "legacy" → sessions/legacy.json
     c. 创建 index.json，activeSession = "legacy"
  3. 如果存在：正常加载 activeSession

运行时：
  context.json 仍写一份当前会话的兼容副本（纯文本 history 数组）
  → 保证其他读 context.json 的代码不崩
```

### SessionManager 接口

```cpp
class SessionManager
{
public:
    explicit SessionManager(const QString &characterPath);

    // 会话 CRUD
    QString createSession();                          // 新建会话，返回 ID
    void saveSession(const QString &sessionId,
                     const QJsonArray &messages);     // 保存会话消息
    QJsonArray loadSession(const QString &sessionId); // 加载会话消息
    void deleteSession(const QString &sessionId);     // 删除会话
    void renameSession(const QString &sessionId,
                       const QString &title);         // 重命名会话

    // 索引操作
    QJsonArray listSessions() const;                  // 列出所有会话（时间倒序）
    void setActiveSession(const QString &sessionId);  // 设置活跃会话
    QString activeSession() const;                    // 获取活跃会话 ID

    // 迁移
    bool needsMigration() const;                      // 是否需要从旧 context.json 迁移
    QString migrateLegacy(const QStringList &history);// 迁移旧数据，返回会话 ID

private:
    QString m_sessionsDir;
    QString m_indexPath;
    QJsonObject m_index;
    void loadIndex();
    void saveIndex();
};
```

### 消息格式升级

```cpp
// 旧：纯文本字符串
QStringList m_contextHistory;
m_contextHistory.append("用户：今天天气好热");

// 新：结构化 JSON 数组
QJsonArray m_currentMessages;
QJsonObject msg;
msg["role"] = "user";
msg["content"] = "今天天气好热";
msg["time"] = QDateTime::currentDateTimeUtc().toString(Qt::ISODate);
m_currentMessages.append(msg);
```

`buildUserMessageWithContext()` 调整为从 `QJsonArray` 构建上下文提示词。

### 退出时保存

在 `Dialog::~Dialog()` 中主动调用 `saveContextHistory()`，确保不丢最后一条消息。同时在 session 切换前也强制保存。

## 风险

- **旧版本升级**：老用户已有 context.json，需自动检测 + 迁移，不丢数据
- **文件 I/O 频率**：每次对话变更都写磁盘可能影响性能 → 沿用 2 秒防抖写入
- **大量会话**：一年可能有几百个会话，index.json 变大 → 限制最多保留 100 个，老旧提示归档
- **记忆系统不变**：memory.json 跨会话共享（用户信息不按会话隔离），不受影响
