# 聊天记录持久化 + 会话切换方案（待实施）

> 2026-07-04 设计 · **2026-08-21 优化**：会话文件改 JSONL（消息即写即存，从根上解决丢最后一条）、全链路原子写、会话 ID 唯一化、索引对账 + 归档淘汰、结构化消息带压缩标记（兼容现有 `角色：[对话摘要]`）、状态机与 `aboutToQuit` 兜底。

## 目标

让桌宠的聊天记录像 ChatGPT 一样：
1. **持久化** — 每次聊天完整保存到磁盘，关掉重开不丢失
2. **会话分离** — 不同时间段的聊天分成独立的"会话"
3. **可切换** — 侧边栏查看所有历史会话，点进去继续聊
4. **新建对话** — 随时开新会话，旧会话自动归档

### 缺的东西

1. **没有"会话"概念** — 所有对话混在一个大数组里，永远追加
2. **没有会话列表** — 用户看不到有哪些历史对话
3. **没有"新建对话"按钮** — 无法主动开始一段新会话
4. **没有会话元数据** — 没有标题、时间戳、消息预览
5. **历史窗口太简陋** — 逐条消息而非分组会话，回溯只能截断不能"切换"
6. **退出时不保存** — 退出前 2 秒内发的消息会丢失（防抖窗口内的最后写入丢失）
7. **rewind 前不保存** — 回溯到历史某条时，当前对话不会先存档

## 设计方案

### 数据格式（优化点 1：JSONL 会话文件 + 原子写）

```
Documents/Mandarin/Character/UserConfig/<角色>/
├── context.json              # 保留：兼容副本（标记 deprecated，见下）
├── memory.json               # 不变
└── sessions/                 # ✨ 会话存档目录
    ├── index.json            # 会话索引（元数据列表）
    ├── 20260704_203015_a3f.jsonl  # 会话1（会话ID = 创建时间戳+随机后缀）
    ├── 20260703_180022_b7d.jsonl  # 会话2
    └── archive/              # 超出上限的会话归档（不硬删）
```

**为什么用 `.jsonl` 而不是单个 JSON**：
- 每行一条消息 JSON，**消息提交即追加**（一次小写入，毫秒级）→ 不再依赖"2 秒防抖"窗口，**从根上解决"退出丢最后一条"**。
- 崩溃最多丢半行（load 时跳过坏行并 `qWarning`），不会损坏整个会话文件。
- 读取 = 逐行 parse，与消息量线性；渲染历史列表天然按序。

**原子写**：所有写盘走 `QSaveFile`（临时文件 + rename）；`index.json` 额外保留 `.bak`。防崩溃写坏。

### 消息 schema（优化点 2：结构化 + 压缩标记）

```json
{"id":"m_1738a1f2","role":"user","content":"今天天气好热啊","time":"2026-07-04T20:30:15Z"}
{"id":"m_1738a1f9","role":"assistant","content":"开心|是啊，夏天真的来了|夏が来たね","time":"2026-07-04T20:30:18Z","meta":{"mood":"开心"}}
{"id":"m_1738a2f1","role":"assistant","content":"[对话摘要] 用户询问排序算法，助手给出了实现","time":"...","meta":{"compressed":true}}
```

- `id`：稳定回溯锚点（`rewind` 按 id 截断，替代按索引）。
- `meta.compressed: true`：对应现有 `角色：[对话摘要] ...` 压缩消息，迁移与渲染兼容（UI 显示为摘要条目而非普通消息）。
- `content` 对 assistant 仍是 `心情|中文|日语|内心独白` **原样存储**，展示时解析；`meta.mood` 冗余存一份便于会话列表预览/统计。

### 会话 ID（优化点 3：唯一化 + 文件名安全）

`yyyyMMdd_HHmmss_<3位随机字母数字>`（如 `20260704_203015_a3f`）。时间戳只到秒会撞车（同秒新建），随机后缀保证唯一；ID 字符集限制为 `[0-9A-Za-z_-]`，天然满足 Windows 文件名安全。

### 索引与对账（优化点 4）

```json
{
  "sessions": [
    {"id":"20260704_203015_a3f","title":"今天天气好热啊","created":"...","updated":"...","messageCount":24},
    {"id":"20260703_180022_b7d","title":"帮我写个排序算法","created":"...","updated":"...","messageCount":18}
  ],
  "activeSession": "20260704_203015_a3f"
}
```

- **启动对账**：扫描 `sessions/` 目录 ↔ index.json——孤儿文件补录、索引里已删除的条目剔除、按 `updated` 倒序。索引与磁盘永远以磁盘为准。
- **上限 100 个**：超出按 `updated` 最旧 → 移到 `sessions/archive/`（不硬删，防误删可找回）。
- `activeSession` 缺失/损坏 → 回退最近 updated 的会话。
- `title`：取会话第一条用户消息前 15 字（后续可改）。

### 迁移（保留 + 细化行解析）

```
启动时：
  1. 尝试加载 sessions/index.json
  2. 不存在（旧版升级）：
     a. 读旧 context.json 的 history 数组
     b. 逐行解析："用户：" / "角色：" / "角色：[对话摘要] " → 结构化消息
        （"[对话摘要]" 前缀 → meta.compressed: true）
     c. 写入 sessions/legacy.jsonl，index.json 的 activeSession = "legacy"
  3. 存在：正常加载 activeSession

运行时：
  context.json 仍写当前活跃会话的兼容副本（纯文本 history 数组）
  → 保证其他读 context.json 的代码不崩；文件头/配置加版本标志标记 deprecated，
    下一大版本移除
```

### 会话状态机（优化点 5：写入时机明确）

| 时机 | 动作 |
|------|------|
| 消息提交 | **立即 append** 当前会话 .jsonl（小写入，无需防抖）；内存数组同步 |
| 压缩后 | 重写当前会话文件（压缩消息已 append，重写用于收拢？——不需要，追加即可） |
| 切换 / 新建 / 删除 | 先 flush 索引（QSaveFile 原子写）再操作 |
| 退出 | `QApplication::aboutToQuit` 钩子兜底 flush（比仅靠析构可靠，析构在部分退出路径不触发） |
| 防抖 | 仅用于 `index.json`（元数据变更不频繁），沿用 2 秒防抖机制 |

### SessionManager 接口（优化：append 语义 + flush + 对账）

```cpp
class SessionManager
{
public:
    explicit SessionManager(const QString &characterPath);

    // 会话 CRUD
    QString createSession();                          // 新建，返回唯一 ID
    void appendMessage(const QString &sessionId,
                       const QJsonObject &msg);       // 追加一条（即时写 .jsonl）
    QJsonArray loadSession(const QString &sessionId); // 读全量消息（坏行跳过）
    void deleteSession(const QString &sessionId);     // 删除（含确认归档策略）
    void renameSession(const QString &sessionId,
                       const QString &title);

    // 索引
    QJsonArray listSessions();                        // 对账后按时间倒序
    void setActiveSession(const QString &sessionId);
    QString activeSession() const;
    void flush();                                     // 原子写 index.json

    // 迁移
    bool needsMigration() const;
    QString migrateLegacy(const QStringList &history);// 返回会话 ID

private:
    QString m_sessionsDir;
    QString m_indexPath;
    QJsonObject m_index;
    void loadIndex();
    void saveIndex();          // QSaveFile + .bak
    void reconcile();          // 磁盘扫描对账
    void evictOverflow();      // 超 100 → archive/
};
```

### UI 设计（优化：搜索 + 预览 + 当前会话高亮）

```
┌─────────────────────────────────────┐
│  对话历史  🔍 [搜索...]      [+ 新建] │
```

- **搜索框**：标题 + 消息内容过滤（≤100 会话、单文件行读，内存过滤足够，无需数据库）。
- **当前活跃会话高亮**，点「继续」切到目标会话。
- **入口**：复用现有历史按钮 `on_pushButton_history_clicked()`。
- 交互：新建 = 保存当前 → 清空 → 开新；继续 = 保存当前 → 加载目标 → 渲染最后一条；删除 = 确认 → 删文件 + 索引（或按策略进 archive）。

### 与现有功能的适配（优化：明确各功能作用域）

| 功能 | 适配 |
|------|------|
| `buildUserMessageWithContext()` | 数据源改为**当前活跃会话**的消息数组（自然形成上下文边界） |
| `compressContextHistory()` | 作用域 = 当前活跃会话；压缩产物写回 `meta.compressed` 消息；60 行阈值不变 |
| `rewindToHistoryIndex()` | 语义变为"截断**当前会话**到某条 id"；rewind 前先 flush |
| 记忆系统 `memory.json` | 跨会话共享，**完全不动** |
| 日程提醒/主动对话等 | 不涉及消息存储，不动 |
