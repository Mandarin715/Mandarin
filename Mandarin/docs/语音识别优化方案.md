# 语音识别准确率优化方案（待实施）

> 2026-08-22 设计。**前提：不更换识别模型**，继续使用 SenseVoice；不引入云端 ASR。目标是在现有管线内提升准确率，重点解决**中文语句夹带的英文缩写被误识别**（如 "GPT" → "GPP"）以及静音/噪声导致的识别质量下降。

## 目标

1. **止血**：让常见英文术语（GPT / API / CPU…）按预期输出，不被误识别、不被后过滤丢弃
2. **清输入**：选对麦克风、去掉送入模型的静音与噪声，减少替换类错误
3. 全程不动模型（不换 Paraformer / Whisper）

## 现状分析（核对当前代码）

| 环节 | 位置 | 现状 |
|------|------|------|
| 采集 | `dialog.cpp:2087-2093` | `QAudioSource`，16kHz / mono / Int16，**写死 `QMediaDevices::defaultAudioInput()`**（无设备选择） |
| 静音停止 | `dialog.cpp:655`、`921-925` | **固定阈值** RMS 静音检测；`SilenceTimeoutMs` 默认 1500ms → 15 帧；阈值默认 0.005 |

### 已定位的问题

1. **英文缩写误识别主因**：SenseVoice 中文优先，英文低频 token 弱；**INT8 量化对低频 token 伤害最大**；`language=auto` 在中文语境下把英文词就近映射成发音相近的错误串。
2. **后过滤对英文缩写敌对**：纯拉丁需 ≥5 字母才有效 → 单独说 "GPT"（3 字母）**会被整句丢弃**（`dialog.cpp:2204`）。
3. **无 VAD**：整段（含首尾静音与环境噪声）直接喂模型，INT8 模型更易产生幻觉/替换错误。
4. **麦克风源写死**：多路输入（外接麦 / 摄像头麦 / 耳机麦）时可能选错源，英文辅音清晰度直接影响缩写识别。

## 设计方案

### A 梯队：止血（不依赖模型改动）

#### A1. 术语纠正表（直接解决本症状）

识别结果上做一次**确定性替换**，把已知误识别纠正为正确术语。

- **配置**：`speechRecognition/corrections`，JSON 数组：
  ```json
  [{"from":"GPP","to":"GPT"},{"from":"A P I","to":"API"},{"from":"C P U","to":"CPU"}]
  ```
- **内置默认**一份常见术语（GPT / API / CPU / GPU / WiFi / UI / UX / Python / GitHub / Docker…），设置页可增删改；
- **应用时机**：`applyRecognizedText()`（`dialog.cpp:2180`）内，**在后过滤之前**（先纠正，再判有效，避免被误丢）；
- **匹配策略**：默认**整词/独立 token 匹配**（不误伤子串），可选大小写不敏感；
- **注意**：不做"万能纠错"，只做用户维护的确定性映射——避免引入新的错误。

#### A2. 放宽后过滤（修掉"整句被丢"）

`dialog.cpp:2204` 的有效性判定改为：

```
有效 = CJK≥1                      // 中文优先，保持宽松
     | 命中术语表任一词            // ✨ 新增：术语白名单直接放行
     | (全字母 且 长度≥2 且 非常见幻觉词)  // 纯英文缩写（GPT/API）不再被丢
```

- 原 `拉丁≥5` 主要用来滤幻觉短词（the / a / is），改为**幻觉词黑名单**（the, a, an, is, it, and, of…）+ 允许 ≥2 字母的纯英文；
- 保证"单独说 GPT"能通过。

#### A3. `language` 参数化（auto → 可配，默认 zh）

- `OfflineSpeechRecognizer.cpp:49` 的硬编码 `"auto"` 改为**可传入参数**；
- 配置 `speechRecognition/Language`（`auto` / `zh` / `en` / `yue` / `ja` / `ko`），默认 `zh`；
- **必须 A/B 实测**（中文为主 + 夹英文时，`zh` 通常比 `auto` 稳，但需用你自己的语音样本确认）。

### B 梯队：清输入

#### B1. 麦克风设备选择

- 设置页加「麦克风」下拉，用 `QMediaDevices::audioInputs()` 枚举所有输入设备（含外接麦）；
- 配置 `speechInput/Device`（存设备描述/ID）；`dialog.cpp:2092` 从 `defaultAudioInput()` 改为按配置选，**找不到则回退默认**（静默降级，不报错）；
- 与摄像头方案同一套设备枚举/降级思路。

#### B2. VAD 裁剪（去掉首尾静音与噪声）

- 新增 `utils/SpeechVad.h/cpp`，封装 sherpa-onnx 的 `VoiceActivityDetector`（Silero）；
- **资源**：新增 `models/silero_vad.onnx`（约 2MB）——**当前 models 目录里没有**，需随包分发；
- **参数（保守起步）**：`threshold=0.25`、`min_silence_duration=0.5`、`min_speech_duration=0.25`、`window_size=512`；
- **流程**：录音结束 → PCM 送 VAD → 取出语音段（多段拼接）→ 只把"人声"送识别；
- **风险控制**：VAD 切出的语音段若短于阈值或为空 → **回退整段送识别**（宁可多送，不可丢话）；
- **v1 边界**：只做"识别前裁剪"，**不改动现有录音停止逻辑**（避免 Record/Stop 行为回归）。

#### B3. int8 → fp32（可选，同模型高精度版）

- `OfflineSpeechRecognizer.cpp:31` 的 `model.int8.onnx` 支持回退到 `model.onnx`（fp32），配置可选；
- **收益**：低频 token（英文缩写）精度回升；
- **代价**：模型体积约 2 倍、解码更慢——用 `num_threads` 1 → 4 缓解；
- **说明**：这是**同一 SenseVoice 模型的精度变体，不是换模型**；若不想动模型文件，此项跳过。

## 明确不做（本次边界）

- ❌ 不更换识别模型（Paraformer / Whisper / 其他）
- ❌ 不引入云端 ASR
- ❌ 不改录音"起停"的核心行为（VAD 仅作用于识别前裁剪）
- ❌ 不做通用 LLM 纠错（只做用户维护的确定性术语表，避免引入新错误）

## 风险

| 风险 | 对策 |
|------|------|
| 术语表误伤（把真的是 GPP 的内容改掉） | 默认整词匹配；用户可控；可在历史记录里看到原文（调试日志） |
| 放宽过滤后幻觉词变多 | 用幻觉词黑名单替代长度阈值；术语白名单只放行已知词 |
| VAD 切掉有效语音 | 保守参数 + 段太短/为空则回退整段 |
| VAD 模型增大安装包 | 约 2MB，可接受；随 `models/` 分发 |
| fp32 性能下降 | `num_threads` 提到 4；配置可回退 int8 |
| 效果不确定（改了很多但没变好） | **阶段 0 的样本采集 + A/B** 是前提，改动逐项验证 |
| `language=zh` 反而让混说变差 | A/B 对比后再定默认值，配置可切回 auto |

## 预期效果（诚实说明）

- **A1 + A2 直接解决"GPT→GPP 且被丢弃"这个具体症状**，确定性高、见效快；
- **B1/B2/B3 是普遍性改善**（输入更干净、低频 token 更准），对"英文缩写"这类问题的帮助是**间接的**，不保证立竿见影；
- 若 A+B 全部做完后英文缩写仍不稳定，根因就在模型本身——那时才需要考虑这次明确排除的"换模型"路线。
