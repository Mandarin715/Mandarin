# Live2D B 阶段：亚托莉手动装扮

2026-09-30。用户授权开始 B 阶段，并允许审查后调整方案。本轮先完成手动装扮，自动剧情触发与 YES/NO 手势不在本轮范围。

## 审查结论

1. 不能把作者的 exp3 直接混进心情覆盖表：心情逐句切换会替换整张表，服装/道具会随之消失。装扮单独持有选择及参数层。
2. 服装和鞋子各是互斥组，不能只增改单条参数。每次选择都先用模型声明 neutral 填满本组所有参数，再写选中的目标值。
3. 热键名称不能作为动作语义的充分依据：YES/NO 指向 Param39，但模型声明显示名是“枕头”。暂不开放，后续须完整出图确认行为及时序。
4. 实测 Param9 单独置 30 显示“睡衣＋南瓜裤”；与 Param18 同开反而看不见裤子。服装菜单选择只启用 Param9。
5. Screen 热键指向 Param31，置 30 会显示半透明屏幕。菜单名称使用“屏幕效果”，不采用误导性的“隐藏屏幕”。

## 使用

用户自行运行 `build2/Release/启动.bat` 后，在亚托莉身上右键打开装扮面板：

面板支持连续换装，选择后保持打开；右键点击面板外部才关闭。下拉选项属于面板内部，点击选项不会关闭面板。外部左键、焦点切换及 Esc 不关闭面板；隐藏角色或重载装扮数据时同步收起。服装、鞋子与道具各使用独立下拉选择，血衣组合和复位同步更新全部选择值。

- 显示／隐藏对话框：保留原右键功能，但改为菜单动作。
- 装扮 → 服装：默认服装、睡衣、泳装、睡衣＋南瓜裤。
- 装扮 → 鞋子：默认、凉鞋、皮鞋。
- 装扮 → 独立开关：眼睛高光隐藏、白眼、屏幕效果、血衣、小鸟、螃蟹、暗淡效果。
- 血衣组合：血衣＋暗淡＋高光隐藏，并恢复默认服装/鞋子，避免与之前选择的服装叠穿。
- 恢复默认装扮：全部回到模型声明 neutral。

选择仅存在当前窗口会话，重载/换模型或重启后恢复默认。未提供装扮表的 Live2D 模型以及 PNG 路径保留原右键直接切换对话框的行为。
没有修改 AI 回复格式、亚托莉提示词、语音配置或用户 config.ini。没有启动桌宠。

## 实现

- `Live2DAppearancePreset.h`：装扮表加载、模型名/声明范围/参数归属校验、互斥选择、组合及复位。解析失败清空装扮功能，非法选择保持原状态。
- `Live2DCharacterWindow`：根据模型名加载可选装扮表，拒绝情绪/标准脸部/呼吸/头发/水印参数，创建常驻工具面板，以 QAction 连接选项并提交独立参数层。`AppearancePanel` 负责外部右键关闭，包含下拉弹窗的归属判断。
- `Live2DOffscreenRenderer`：在动作、情绪、眨眼、口型、待机摆动及物理之后，在 `Update()` 之前施加装扮值；不写进 `SaveParameters()` 基线，防止复位留下残留。
- `appearance.json`：9 组、21 个选项、1 个组合，拥有 12 个模型参数。版本化副本在 `assets/live2d-presets/atri/presets/`；运行时副本在 `Documents/Mandarin/Character/Assets/亚托莉/Live2D/atri/presets/`。

表内只含我们自己的映射数据，数值由 moc 声明核对，不修改或复制作者的模型文件。现有渲染线程和音频胶水层没有改动。

## 下一步建议

2026-09-30 交互修复：新增 `appearancePanelStaysOpenUntilOutsideRightClick`，通过实际鼠标选择连续换装、组合/复位联动、外部左键不关闭、外部右键关闭与焦点/Esc 行为。专项日志在 `build2/appearance-panel-ui.log`；主程序 Release 已构建。

点头/摇头应单独做可打断、自动回中的短动作，而非永久开关；先实测 Param39，不从热键名字猜测。

2026-09-30 后续交互调整：关闭手势改为外部右键，新增装扮标题栏，按住左键拖动面板；控件点击不触发拖动。右键点击角色关闭面板时吞掉同一次上下文菜单请求，避免立即重开。测试覆盖拖动位移、移动后连续换装和该关闭路径。

右键防重开补修：原实现只在 Qt 鼠标事件路径记录精确坐标，Windows 外部点击轮询关闭时未记录，且按下/上下文事件坐标稍有变化就失效。现在两条关闭路径统一通知角色窗口，拦截同一次右键的上下文事件；新的右键按下清除旧状态。轮询只处理 Qt 窗口之外的点击，避免与 Qt 事件路径竞争。回归覆盖坐标移动、轮询路径、面板销毁、下一次正常打开及外部点击未产生 Qt 上下文事件的情况。日志 build2/appearance-dismiss-transaction.log。

人物内部右键补修：复现原生 QWindow 先收到按下、再向 QWidget 派发的真实事件顺序；旧实现把非 QWidget 来源误判成外部，提前关闭后导致角色上下文菜单再次打开。事件过滤现在仅处理 QWidget 派发，并将角色自身右键统一交给 contextMenuEvent：面板已打开则关闭并返回。回归选取模型实际不透明像素，而非旧测试的透明边角；原生按下/抬起、上下文事件及后续重新打开均覆盖。旧实现日志 appearance-avatar-native-red.log 明确失败 Native QWindow press prematurely dismissed the panel，修复后的专项日志 appearance-avatar-native-final.log。

同次点击的重复上下文请求：原生 QWindow 的鼠标抬起会自动产生上下文请求，随后平台还可能再次请求菜单。关闭标记现在保留到下一次右键按下，避免只拦截一次后又重开。回归在人物不透明像素上依次发送原生按下/抬起与额外上下文事件，既验证关闭也验证下一次点击正常打开。
