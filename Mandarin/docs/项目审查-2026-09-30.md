## 仍需推进的问题

### P2：启动补播会先删除提醒，再尝试发声

`Dialog::catchUpMissedSchedules` 先从列表删除 24 小时内的一次性提醒，再调用 `doProactiveSpeak(... forced=false)`，且没有检查返回值。关闭主动对话、处于冷却、用户离开或业务忙碌时，调用可直接拒绝，但提醒仍会保存为已删除。普通到点提醒已有“成功受理才删除”的处理。

建议补播独立于闲聊开关，只有成功受理才删除；拒绝时保留并重试。若还要保证网络失败后也不丢，需要进一步区分“待发送、请求中、已交付”。这里是静态确认，尚未添加 Dialog 日程集成测试。

### P2：记忆与日程写入仍会直接截断原文件

`Dialog::saveMemory`、`saveSchedules`，以及记忆设置页删除/清空的写入，使用普通 QFile 覆盖。写入中断或磁盘写入失败可能损坏整份数据；部分 UI 在写入失败后仍展示成功。

建议统一使用 QSaveFile 原子提交，把写入结果返回调用者，再刷新缓存和显示成功。聊天记录整文件重写已经采用 QSaveFile，可以沿用同一种约定。

### P2：OAuth 请求缺少独立认领和失效控制

搜索 token 请求未跟踪当前 reply，重复搜索可同时换 token；修改密钥后，旧 token 的晚到响应仍会覆盖缓存。普通搜索已有 reply 认领保护，但 token 分支没有。

建议增加 token reply/generation，配置变化后废弃旧响应；正在获取 token 时合并到最新查询。需要 mock OAuth 服务测试旧响应晚到，本轮不访问真实外部接口。

### P2：记忆列表删除依赖可能过期的索引

记忆行保存显示时的数组下标，点击时却重新读取当前角色文件。角色切换未自动刷新记忆页，后台记忆条目变化也可能导致列表与文件下标不同，从而删除另一条记录。

建议给条目稳定 ID，或在点击时验证角色和条目内容仍匹配；角色切换时刷新该页面。

### P3：导入导出与网络设置的交互问题

- 角色 ZIP 导入/导出在 GUI 线程 `waitForFinished(60000)`，大资源处理期间界面和动画会停顿。建议 QProcess 异步信号驱动进度、完成与取消。
- Windows 导入/导出的 PowerShell 字符串直接包单引号路径，含单引号的文件名会破坏参数。建议用参数化脚本或统一转义。
- VITS 模型列表刷新和更新下载没有传输超时。列表刷新允许重复请求，旧响应可以覆盖新接口地址的结果。建议请求超时、在途按钮状态与 generation 保护。
- DragHelper 只在鼠标 release 时清理拖动状态，未处理失去 grab、隐藏或取消；应增加取消路径，并以真实按钮状态保护移动。透明区域的拖动接受策略也应由角色窗口提供。

## 优化建议（按顺序）

1. **先补业务状态测试。** 当前几何、渲染、参数、装扮测试较多，Dialog 的队列取消、网络乱序、提醒和退出流程缺乏可隔离的集成测试。优先提取请求/播放控制器，注入网络与播放器替身。
2. **拆分 Dialog。** 接近 5,000 行，同时承担输入路由、AI、TTS、记忆、摄像头、日程与主动对话。可先拆 ReplyPresentation 与 VitsPipeline，再拆 ScheduleStore/ReminderController；每次保持原有信号合同。
3. **测量 GPU 读回成本。** Live2D 每帧 `glReadPixels` 后再 `glFinish`，随后镜像复制为 QImage；高 FPS、DPR 和 supersampling 同时增大读回及拷贝成本。先测帧耗时和占用，再评估去掉多余同步、复用缓冲、PBO 或直接 OpenGL 窗口。默认 FPS 的整数毫秒计算也无法精确表达 120Hz，需用累计时间或明确档位。
4. **减少主线程视觉等待。** FaceDetector 每次检测都创建 WinRT detector 并同步 `.get()` 等待两次异步任务。建议复用 detector，并在独立、正确初始化 COM 的线程运行；需先测量延迟。
5. **统一配置与存储职责。** 页面边输入边写盘并触发重载，初始化时各页信号阻塞策略也不同。建议明确“读取初始化”和“用户修改”的边界，文本类设置加短防抖，集中处理写入失败。
6. **整理构建警告。** Release 仍有既存 LNK4199（无实际导入的 DELAYLOAD），离屏测试有 LNK4098（默认 CRT 库冲突）。建议统一运行库选项并清理未生效链接选项，本轮构建成功不等于这些警告已解决。
