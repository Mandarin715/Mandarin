# 摄像头视觉感知方案（待实施）

> 2026-07-06 原设计（v2.0 追加，暂不实施）· **2026-08-22 重定向**：核心从"常开感知"改为「**按需短开验证**」——平时摄像头完全关闭，仅当键鼠信号"怀疑"状态变化时短开 2-3 秒确认；v1 范围收窄为**仅人脸存在检测**（砍掉表情/情感/视线）；新增**外接摄像头设备选择**（用户用外置显示器，需外接 USB 摄像头）；人脸检测首选 Windows 内置 FaceAnalysis（零新增依赖），备选 onnxruntime 轻量模型。

## 目标

在主动对话基础上接入摄像头，让桌宠能"看见"用户，**但以最小隐私与观感代价**：
1. 分辨「**在看视频没操作**」与「**人真的走了**」（现有键鼠推断做不到）
2. 不碰键鼠也能发现用户回来
3. 真正实现"不打扰"（打电话/吃饭时安静）

### 盲区（摄像头要解决的）

1. 看视频/长文档无输入 → 被误判"离开"（30 分钟）
2. 人坐回来但不碰键鼠 → 感知不到"回来"
3. 人在打电话/吃饭 → 无法区分，可能误触发问候

### 无摄像头代码

`dialog.h` 无 `QCamera` 相关成员，摄像头感知**尚未实现**。

## 设计方案

### 核心转变 1：按需短开验证（已定）

**摄像头平时完全关闭。** 只有"怀疑"时才开：

```
平时：摄像头 OFF（零隐私占用，指示灯不亮）
  ↓ 键鼠空闲超过怀疑阈值（默认 10 分钟，可配）
怀疑阶段（免费）：判定"可能离开" → 触发一次验证突发
  ↓
验证阶段：短开摄像头 2-3 秒，抓几帧做人脸检测 → 立刻关
  ├─ 有人脸 → 用户在场（看视频/发呆）→ 不判离开，维持现状
  └─ 无人脸 → 判定"离开"（m_userAway = true）
      ↓ 离开期间每 3-5 分钟一次 2 秒短检
      └─ 有人脸 → 判定"回来"（触发原有回来问候，受冷却约束）
```

- **有键鼠输入 → 立即取消怀疑**（无需开摄像头）；
- 原"无输入 30 分钟判离开"逻辑被摄像头验证**替换**；摄像头不可用/被拒 → **回退旧键鼠推断**；
- 原"回来问候"（`dialog.cpp:3485`）与"空闲轻度问候"（`dialog.cpp:3509`）保留，只是触发依据部分换成摄像头结果。

### 核心转变 2：v1 仅人脸存在（已定）

- 检测输出只有：`facePresent` / `noFace`；
- **不做**表情（笑/累）、视线（看屏幕 vs 别处）、情感分类——模型重、占用久、收益不确定，v2 再议；
- 摄像头占用被压到"每次 2-3 秒突发"，隐私与资源代价可接受。

### 核心转变 3：人脸检测依赖（已定，实现前 spike 验证）

| 方案 | 优点 | 代价 | 结论 |
|------|------|------|------|
| **Windows.Media.FaceAnalysis**（WinRT） | 零新增依赖、零模型体积、快而准 | 需 C++/WinRT 桥接；仅 Windows | **首选**（摄像头功能本就 `Q_OS_WIN` 限定） |
| onnxruntime + 轻量人脸 ONNX 模型 | 跨平台 | sherpa-onnx 已打包 onnxruntime，需确认能否拿到通用推理入口 | 备选 |
| OpenCV | 生态全 | 体积大、构建重 | 仅前两者都不行再考虑 |

> **实现前先做半天 spike**：flash 验证 WinRT FaceAnalysis 在本机 MSVC/Qt 环境能否编译取帧检测；不行就退 onnxruntime。

### 外接摄像头设备选择（已定）

用户使用**外置显示器 + 外接 USB 摄像头**，设计须支持设备选择：

- 用 `QMediaDevices::videoInputs()` 枚举所有可用摄像头（内置 + 外接 USB）；
- 设置页加「摄像头选择」下拉，配置记住所选设备（如 `cameraPerception/Device`，存设备描述/ID）；
- **启动校验**：所选设备不在 → 静默降级回键鼠推断（不弹错打扰）；拔插后下次启动自动重拾。

### 新增设置（默认关闭）

| 配置键 | 说明 | 默认 |
|--------|------|------|
| `cameraPerception/Enable` | 摄像头感知总开关 | **关** |
| `cameraPerception/Device` | 所选摄像头设备 | 空（自动选第一个可用） |
| `cameraPerception/VerifyIdleSec` | 怀疑阈值（无输入秒数触发验证） | 600（10 分钟） |
| `cameraPerception/AwayRecheckSec` | 离开期间短检间隔 | 180~300（3-5 分钟） |

## 风险

| 风险 | 对策 |
|------|------|
| 隐私 / 摄像头指示灯常亮 | **按需短开为本方案核心**：平时 OFF，仅 2-3 秒突发验证 |
| 外接摄像头拔掉 / 换口 | 启动校验 + 静默降级键鼠推断，不打扰 |
| WinRT 桥接在本环境失败 | spike 先行；备选 onnxruntime 轻量模型（复用 sherpa-onnx 的 onnxruntime） |
| 误判（人在但检测不到脸） | 怀疑阈值/短检间隔可配；检测失败按"不确定"处理不判离开 |
| 占用资源 | 突发短开 + 低分辨率帧（如 320x240）检测 |
| 仅 Windows | v1 `#ifdef Q_OS_WIN`；macOS/Linux 摄像头感知留后续 |
| 摄像头选择 UI 复杂度 | 枚举失败/无设备时隐藏设置项并提示 |
