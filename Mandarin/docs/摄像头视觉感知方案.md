# 摄像头视觉感知方案（v2.0 追加，暂不实施）

> 2026-07-06 设计，在主动对话 v2.0 基础上的可选追加

## 目标

在主动对话方案基础上接入摄像头，让桌宠能"看见"用户。**本方案不替代 v2.0 的任何内容，仅追加和替换部分。**

## 摄像头替代了什么

| 功能 | v2.0 实现 | 加摄像头后 |
|------|----------|-----------|
| 用户离开检测 | `GetLastInputInfo()` 轮询键鼠 | **摄像头人脸检测**——比键鼠更准，能区分"离开"和"在看视频没操作" |
| 用户回来检测 | `GetLastInputInfo()` 突然有输入 | **摄像头人脸检测**——没碰键鼠但人坐回来了也能感知 |
| 交互状态判断 | 只能通过窗口 + 输入推测 | 摄像头能直接看到"用户在看屏幕"还是"在打电话"还是"吃东西" |
| 情感感知 | 无 | 摄像头人脸表情 → 心情适配，"你看起来好累，休息一下吧" |
| 截图触发频率 | 定时 N 分钟 | 摄像头先判断用户状态再决定要不要截屏，减少无效 API 调用 |

## 不替代的内容

| 功能 | 保留原因 |
|------|---------|
| 窗口标题检测 | 摄像头不知道你在用什么软件 |
| 空闲时间 + 时段 | 摄像头不需要关心"几点" |
| 截图 + Vision | 摄像头不知道屏幕内容是什么 |
| 决策上下文 | 照常构建，摄像头结果作为额外信息源 |

## 新增的能力

### 1. 人脸存在检测

```
摄像头每 5 秒采样一帧 → 轻量人脸检测（OpenCV/系统API）
  → 有人在 / 没人在
  → 替代 GetLastInputInfo 做离开/回来判断
```

不需要人脸识别（不需要知道是谁），只要检测有没有人脸。

### 2. 用户状态感知

```
人脸检测基础上加：
  - 用户在看屏幕 vs 看别处（头部姿态）
  - 用户在笑 vs 面无表情（表情分类）
  - 用户在打电话（手机贴耳朵）
  
→ 这些状态直接写入决策上下文：
  "[用户状态] 正在专注看屏幕，表情认真"
  "[用户状态] 低头看手机，不在看电脑"
```

### 3. 精准不打扰

摄像头能判断"用户虽然在电脑前但没在操作"（比如在吃饭、打电话）。v2.0 只通过键鼠判断，会把这种场景误判为"空闲"然后触发主动对话——不合适。摄像头能避免。

## 新增场景

| 检测到 | 主动说什么 |
|--------|-----------|
| 用户一直盯着屏幕不动 | "盯了这么久屏幕，眼睛不累吗？休息一下吧～" |
| 用户对着屏幕笑 | "看到什么了这么开心？分享给我听听～" |
| 用户揉眼睛/打哈欠 | "你看起来好累，要不要早点休息？" |
| 用户离开座位 | 不再触发主动对话（v2.0 靠键鼠判断有空窗期） |
| 用户端着杯子回来 | "你回来啦！泡了什么好喝的？" |
| 用户打电话 | 安静不打扰 |

## 技术实现

```cpp
// Qt6 原生摄像头，约 20 行
QCamera *camera = new QCamera(QMediaDevices::defaultVideoInput());
QMediaCaptureSession session;
QVideoSink *sink = new QVideoSink;
session.setCamera(camera);
session.setVideoSink(sink);

connect(sink, &QVideoSink::videoFrameChanged, [=](const QVideoFrame &frame) {

camera->start();
```

人脸检测用 OpenCV 或系统 API（Windows 用 `Windows.Media.FaceAnalysis`），本地运行，不消耗 API 额度。

## 风险

- macOS 需 `NSCameraUsageDescription`
- 人脸检测模型增加 ~5MB 编译产物
- 隐私：摄像头数据不存储、不上传（仅本地推理）
- 摄像头权限弹窗可能吓到用户
